# Internationalization

LealFinance ships in Brazilian Portuguese (`pt-BR`) only for now, but the
whole i18n setup is built as if more languages exist — adding one later
should be a config + translation-file change, not a rewrite.

## Where things live

- `frontend/src/app/core/transloco.providers.ts` — `provideTransloco`,
  `provideTranslocoLocale`, `provideTranslocoPersistLang`. This is the one
  place language config lives.
- `frontend/public/i18n/pt-BR.json` — translation strings. Angular 22's
  default static-assets directory is `public/`, not the legacy
  `src/assets/`; a custom `TranslocoLoader`
  (`frontend/src/app/core/transloco-loader.ts`) fetches from `/i18n/{lang}.json`
  to match.
- `frontend/transloco.config.js` — config for the `transloco-keys-manager`
  CLI (finds missing/orphaned keys; not used at runtime by the app itself).

## Rule: the backend never translates anything

The API returns machine-readable error codes, never translated strings:

```json
{ "error": { "code": "account.insufficient_balance", "params": { "available": "150.0000" } } }
```

`app/core/errors.py` (`AppError` + `app_error_handler`) enforces this
shape. The frontend maps `code` to a Transloco key itself (prefixing with
`errors.`, say). This keeps every translation in exactly one place — adding
a language never touches the backend.

## Rule: no hardcoded strings in templates

Every user-facing string goes through Transloco (`*transloco="let t"` +
`t('some.key')`, or the `TranslocoDirective`/pipe). Run
`task i18n:validate` (`transloco-keys-manager find`) before committing
frontend changes — CI enforces this too, and it catches both missing keys
(used in a template, absent from `pt-BR.json`) and orphaned ones (present
in the file, no longer referenced).

One gotcha: the key-finder scans `.ts`/`.html` source text for calls
matching the configured marker (default `t`), including inside comments —
a docstring showing an example call like `` `t('foo.bar')` `` as literal
text will register as a false "missing key". Word example calls so they
don't look like literal invocations (see the comment in
`frontend/src/app/core/api-error.ts` for the pattern).

## The language switcher exists on purpose

`frontend/src/app/layout/shell.ts` has a language switcher in the nav, even
though there's only one language to switch to. This is deliberate — it
forces the runtime-language-change plumbing (`reRenderOnLangChange: true`,
`transloco-persist-lang`) to be real and tested now, rather than something
bolted on awkwardly when a second language actually arrives.

## Layout: pt-BR runs longer than English

Brazilian Portuguese strings are typically 20-30% longer than their English
equivalents. Don't build fixed-width buttons, don't truncate nav/table
labels by default, and check any new layout at a narrow viewport (320px)
before assuming it holds up.

## Currency formatting

`MoneyPipe` formats amounts using `TranslocoLocaleService`, which derives
locale-appropriate grouping/decimal separators and the correct number of
decimal digits per currency from `Intl.NumberFormat` — no hardcoded `2`.
See [`money-and-currency.md`](money-and-currency.md) for the more important
rules around amount *precision* (this file is about *language*, that one's
about *numbers*).
