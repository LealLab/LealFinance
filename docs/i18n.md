# Internationalization

English (`en-US`) is the default interface language. Locale catalogs live in
`frontend/public/i18n/{lang}.json`; the available catalog files are the source
of truth for supported languages.

## Where configuration lives

- `frontend/src/app/core/transloco.providers.ts` configures Transloco and the
  saved language preference.
- `frontend/public/i18n/{lang}.json` contains translated strings.
- `frontend/transloco.config.js` configures the translation-key checker.

The custom loader fetches catalogs from `/i18n/{lang}.json` because Angular 22
serves `public/` as the static-asset root.

## Translation rules

The backend returns machine-readable error codes, never translated messages:

```json
{ "error": { "code": "account.insufficient_balance", "params": { "available": "150.0000" } } }
```

The frontend maps the code to a Transloco key. Keep translations in the
frontend so every language uses the same API contract.

Every user-facing template string must use Transloco. Run this before a
frontend change is committed:

```bash
task i18n:validate
```

The check finds missing and orphaned keys, incomplete locale files, and
placeholder changes. It scans source comments too, so example calls that look
like real translation calls can be reported as false missing keys.

## Language preferences and layout

The language switcher is available from the application shell and Settings.
Changing language also updates document direction and locale formatting.
Arabic (`ar`) and Hebrew (`he-IL`) use right-to-left layout.

Language and currency are separate preferences. Do not assume that changing
one changes the other. New layouts must also handle longer translations and a
320px viewport; avoid fixed-width labels and buttons.

`MoneyPipe` uses the active locale and the currency's own decimal-digit rules.
See [`money-and-currency.md`](money-and-currency.md) for storage and precision
rules.
